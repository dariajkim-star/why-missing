# why-missing — 부재 판정기 (Absence Adjudicator)

> **이 도구가 답하는 질문**: *"이 회사의 이 금액, 왜 표준 XBRL에 없지?"*
>
> (회사, 잔액형 재무 개념)을 입력하면 — 부재의 6형태 중 어디인지, 근거 한 줄과 함께,
> 30초 안에 답하는 **실사(due diligence) 보조 도구**.

## 부재의 6형태 (실증 분류 — 46곳 10-K 검증)

| 형태 | 뜻 | 기계 판별 |
|---|---|---|
| ① 진짜 누락 후보 | 어디에도 없음 — **"확인 필요"로만 출력** (확정 문구는 시스템이 낼 수 없음) | 잔차 |
| ② 다른 곳 기재 | 상위·병렬 태그로 이미 공시 | ✅ |
| ③ 파생 가능 소계 | 구성요소가 있어 계산되는 값 | ✅ |
| ④ 해당 없음 | 그 사업에 그 항목이 원래 없음 | ⚠️ 부분 |
| ⑤ 정당한 0 | 제도는 살아있고 당기 금액이 0 (흐름 개념 — **입력 거부**) | ❌ |
| ⑥ 업종 동음이의 | 같은 단어, 다른 뜻 (광권 lease 등) | ⚠️ 목록 성장 중 |

## 상태

- **TRL 3 → 4 진행 중**: 개념 실증 완료(스파이크 1~6, 사전등록 kill criteria 3연속 발동·기준 불변),
  스캐폴딩·테스트 고정이 다음 단계. 완성 기준 M1~M4는 [MVP 브리프](docs/mvp-brief-absence-adjudicator.md).
- **전신**: [crm-targeting-lab](https://github.com/dariajkim-star/crm_targeting_lab) — 방법론 리허설
  (동결 보존, 401 tests). 이 저장소가 정본이고 crm 쪽 문서는 역사 기록.

## 영구 단서 (이 저장소의 모든 산출물에 적용)

**"46곳 검증에서 확인된 진짜 누락 0곳"은 "누락이 없다"가 아니다** — 탐지력이 검증 불가로
남았기 때문이다(양성 대조군 표본 미달). 이 단서 없이 결과를 인용하는 것은 오용이다.

## 이식 계약 9건

리허설에서 검증·확정된 계약 (THESIS 결정 대장 참조): 개념별 부재 정의 · 두 데이터셋 부재 ·
큰 회사 자기의심 규칙 · 공변량 보정(층화 금지) · 금액 축 동행 · peer=SIC4/n≥10/판정불가 ·
OTC 물리분리 · SEC 취득 규약 · **데이터 계보·무결성**(CIK–accession 행 필수 · 404≠부재 ·
상위 변경 시 하위 미재계산=테스트 실패).
