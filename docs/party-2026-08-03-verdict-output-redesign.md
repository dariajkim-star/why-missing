**첫 파일럿 사용자가 첫 실행에서 출력을 오독했다.** daria의 첫 반응: "도구가 틀린 판정을 했네."

후보를 결론처럼 읽히게 했다.**

M4는 `"누락 확정"은 출력 불가`를 요구한다. 우리는 금지어를 쓰지 않았지만
**금지어의 발음을 맨 윗줄에 대문자로 출력하고 있었다**(Paige).

## 1. 🔴 파티의 최대 발견 — 도구가 자기 답을 손에 들고 있었다

세 번째 줄:

```
tags seen: FiniteLivedIntangibleAssetsAccumulatedAmortization
```

**상각누계가 잡혀 있다.** 회계적으로 이는 중립 정보가 아니라 **①에 대한 반증**이다 —
상각누계가 존재한다는 것은 상각할 무형자산이 존재하고, 그것이 **어딘가에 공시됐다**는 뜻이다
(레아).

즉 도구는 ② 근거를 **수집해서 화면에 인쇄까지 해놓고**, `tags seen`이라는 무표정한 라벨 밑에
깔아둔 채 맨 위에서 "누락 후보"를 외쳤다.

> 이 프로젝트가 여섯 번 잡은 실수는 **부재를 증거로 착각하기**였다.
> 이번엔 그 거울상을 저질렀다 — **존재를 무시하기.**

**따라서 원인은 능력 부족이 아니라 출력 구조다.** 단일 verdict 라벨은 이 회사의 실제 상태를
담을 수 없다(상각누계 있음 → ②로 기울고, 표준 태그 없음 → ①도 완전 배제 불가).
**단일 라벨을 요구하는 순간 도구는 거짓말을 하게 되어 있다**(Winston).

## 2. 안건 2 판정 — ②③을 판정할 수 있는가

| 범주 | 기계 판정 | 근거 |
|---|---|---|
| ② 다른 곳 기재 — **태그 근거** | ✅ 가능 | 상위·병렬 태그, 파생 가능 소계. 스파이크4에서 94→16을 이 방식으로 절단 |
| ② 다른 곳 기재 — **문장 근거** | ❌ 불가 | XBRL에 없는 것을 XBRL로 찾을 수 없다. **RGR이 정확히 이 경우** |
| ③ 애초에 0 | ✅ 대체로 가능 | 잔액 개념은 대차 항등식으로 검산. 흐름 개념은 불가이나 **계약 4가 입구에서 거부** |
| ① 진짜 누락 | ⚠️ 확정 불가(영구) | 탐지력 미검증(스파이크5 X1 미달). M4가 확정 출력을 금지 |

**결론: 약속을 줄이지 않는다.** 3분류 중 **②③은 실증적으로 작동한다**(마감 문서의 판정).
못 하는 것은 **문장으로만 적힌 ② 하나**뿐이다.

🔴 **단, 그럼발 조건 — 그 하나가 대표 사례다.** FINDINGS 간판 3개 중 첫 번째(Sturm Ruger)가
문장 ②다. 커버리지가 넓다고 말하지 말고 **못 하는 것을 이름으로 명시**할 것.

### 안건이 뒤집힌 지점

우리는 *"도구가 ①밖에 **못 한다**"* 고 물었는데, 답은 *"도구가 ①밖에 **말하지 않는다**"* 였다.
3분류에서 **확실한 것은 ②③, 불확실한 것은 ①**인데, 도구는 확실한 둘을 감추고 불확실한
하나만 외치고 있었다. 줄여야 할 것은 3분류가 아니라 **①의 목소리 크기**다(레아).

## 3. ✅ daria 승인 결정 3건

### 결정 1 — 단일 verdict를 버리고 **순위 매긴 소견**으로 (승인)

판정 로직 불변, **출력 계약 변경**. (원 안건은 "엔진 불변"이었으나 방이 경계를 넘겼고
daria가 승인.) 목표 형태:

```
자동 확인 불가 · 사람이 10-K 원문을 확인해야 함
가장 유력: ② 다른 곳 기재 — 상각누계 태그 존재(무형자산이 있고 어딘가 공시됐다는 뜻)
배제 못 함: ① 진짜 누락 — 표준 태그가 두 데이터셋 모두에 없음
내가 못 보는 문: 주석 본문의 문장 공시 · 차원 태그
peer 비교 : 없음(캐시 부재) — 이 소견은 공시 한 건에만 근거함
```

M4와 충돌하지 않는다. 누락을 확정하지 않으며, **확정 못 하는 것을 맨 위에서 외치는 것**을
그만둘 뿐이다.

### 결정 2 — 관측값 동반 의무를 계약으로 (승인)

> **"가장 유력"에는 반드시 관측값 한 줄이 붙는다. 붙일 수 없으면 순위를 표시하지 않는다.**

근거 없는 순위는 신탁이다(그럼발). 배제리스트 설계 때 확립된 "이유 줄은 관측값을 인용한다"
(Sally)의 출력 계층 판이다.

### 결정 3 — 순서: **적중률 측정 먼저, 렌더러 나중** (승인)

이 방은 화면 **한 장**을 보고 논의했다. 증거규칙(상각누계 → ② 가중)이 실제로 ②를 골라내는지는
**미측정**이다(그럼발). 스파이크4 무형자산 전수 23곳이 이미 정답지로 커밋돼 있으므로
(`docs/m1-golden-reproduction.md`), 새 소견 규칙을 거기에 돌려 **분류 적중률을 먼저 센다.**
새 데이터·가격 API 불필요. **결론이 굳기 전에 설계를 바꾸지 않는다**는 이 프로젝트의 규율 적용.

## 5. 구현 범위 (Amelia 견적)

판정 로직 변경 아님. `tags seen`을 이미 수집 중이므로 **가중과 렌더링**이 작업이다.

1. 형태별 증거규칙 테이블 — 태그 존재 → 6형태 가중
2. 출력 렌더러 교체 — 순위 소견 + 관측값 한 줄(결정 2)
3. **회귀 테스트**: `CANDIDATE_OMISSION`이 첫 줄에 오면 **실패**하는 문서-계약 테스트(M4 확장)
4. `peer ctx` 부재 사유 분리(없음 / 조회 실패)

3번이 핵심이다 — 나중에 누가 되돌려놔도 빨간불이 켜진다(그럼발).
